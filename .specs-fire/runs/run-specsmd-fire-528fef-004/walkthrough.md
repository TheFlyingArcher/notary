# Implementation Walkthrough: Leaf certificate validity dropdown

## Summary

The Create Certificate page's free-text "Expiration" field is now a dropdown of the leaf validity periods: 30 days, 90 days, and 6, 12, 13 and 24 months. 12 months is preselected and tagged recommended. Options that would outlive the selected issuing CA are disabled with a reason; a self-signed certificate has no cap.

## Structure Overview

The page asks `ValidityPolicy.Evaluate` for leaf options each render, capped at the selected CA's `NotAfter`. `RefreshValidity()` keeps `SelectedPeriod` consistent with them and runs after the issuing CA changes (including switching to self-signed) and on page load. Submit computes `notAfter` from the selected period, using months or days as appropriate.

## Key Implementation Details

### 1. Removed 12-month minimum

The old validator rejected anything under 12 months, which would have blocked the 30 and 90 day options. The dropdown now defines what is allowed, and the server-side check from the earlier work item rejects anything past the issuer.

### 2. Selection rules

Same as the CA page: keep the current choice if still allowed; otherwise the recommended one, otherwise the longest allowed one, otherwise none (select disabled with an explanatory message, Required blocks submit).
