# Implementation Walkthrough: CI check for FIRE state consistency

## Summary

A Node script compares `.specs-fire/state.yaml` with every intent brief and work item file and fails when statuses disagree. A path-filtered workflow runs its tests and the check on pull requests that touch FIRE files. `--fix` repairs the status values locally.

## Structure Overview

`check-fire-state.cjs` reads state with the `yaml` Document API, derives the expected intent status from its work items, and compares it with the state and the front matter of each file. Fixes are targeted line edits, so formatting and line endings survive. `fire-state.yml` installs `yaml` into a temporary directory (no `package.json` in the repository), runs the unit tests, then the check.

## Decisions Made

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Source of truth | `state.yaml` for item statuses | The Builder scripts write it; files follow it |
| Required check | No | A `paths`-filtered workflow stays pending when it does not run |
| Pending intents | Allowed only when the intent and every item are pending | Planned work should not be forced to `in_progress` |
| Run scripts | Not patched | The gap in `complete-run.cjs` is vendored; `--fix` covers it, and it should be reported upstream |
| Tests | `node:test` with temporary fixtures, no real-repo test | Keeps the unit tests hermetic; the check step covers the real repository |
