# Implementation Walkthrough: Selective CI and CodeQL runs

## Summary

CI and CodeQL now run only when a change can affect the .NET code. A shared script decides this from the git diff. Docs-only pull requests skip the build, tests, coverage gate and CodeQL scan but still show the required checks as passing, and a docs-only merge to `main` publishes no tag or image.

## Structure Overview

`detect-dotnet-changes.sh` is the single owner of the path list. Each workflow starts with a small `changes` job that runs it and exposes `dotnet=true|false`. The heavy jobs (`quality`, `analyze`) depend on `changes` with a job-level `if`, and `release` depends on `quality`, so it is skipped with it.

## Security Considerations

| Concern | Approach |
|---------|----------|
| Script injection from event data | SHAs and event name reach the script only through `env:` |
| CodeQL permissions | `contents: read` and `security-events: write` on the analyze job only |
| Wrongly skipped scan | Pushes to `main` and a weekly schedule always scan |

## Decisions Made

| Decision | Choice | Rationale |
|----------|--------|-----------|
| How to skip | Job-level `if` after a detection job | Workflow-level `paths:` leaves required checks pending; a skipped job counts as passing |
| Path list | One shell script shared by both workflows | One place to change; no third-party action |
| Relevant paths | `src/`, `Notary.AppHost/`, `Notary.ServiceDefaults/`, the two workflows and the script, plus props/targets, `global.json`, `nuget.config`, `.editorconfig`, `.globalconfig` anywhere | Everything that reaches the build, the Docker image, or CI itself; `deploy/` and `docs/` are not built |
| Uncertain cases | Run everything | Running too much is harmless, skipping is not |
