# Walkthrough: Download format catalog and file name builder

## Summary

Added a stateless catalog that describes each download format in plain language, plus a builder for the downloaded file name. The download dialog does not use it yet; that is the next work item (`download-dialog-ui`).

## Structure Overview

`CertificateDownloadCatalog` (static, in `Notary.Download`) holds one `CertificateDownloadOption` record per `CertificateFormat`. The dialog will read labels, blurbs and the password flag from it and call `BuildFileName` instead of the current extension `switch`. It sits in the core library beside `Validity` and `Profiles`, which also hold UI-facing policy that the test project can reach.

|------|--------|

| `src/library/core/Download/CertificateDownloadCatalog.cs` | New: `All`, `For(format)`, `BuildFileName(format, requestedName, certificateName)` |
| `src/test/CertificateDownloadCatalogTest.cs` | New: 32 tests |

## Key Decisions

| Decision | Why |
|----------|-----|
| Catalog lives in `src/library/core`, not `src/web` | The test project does not reference `Notary.Web`; core is testable and matches existing patterns |
| File names: typed value, else certificate name, else `certificate` | A name that is empty after stripping must still produce a usable file |
| Trailing copy of the extension is removed before it is re-added | Typing `server.pem` must not produce `server.pem.pem` |
| Both `.p7b` formats share an extension | Matches the previous dialog behavior |

## Security Considerations

| Concern | Approach |
|---------|----------|
| Path traversal in a user-typed name | `/`, `\` and all invalid file name characters are removed and leading dots are trimmed, so `..\..\x` becomes `x` |
| Private key exposure | Only `Pkcs12` is flagged `ContainsPrivateKey` and `RequiresPassword`; a test enforces it |
